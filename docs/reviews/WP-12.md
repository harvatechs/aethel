## 1. Compliance with Rules and Anti-Patterns
- **Twelve Non-Negotiables**:
  - Strict or reject: `AttestationEnvelope` and `ChunkProof` reject non-canonical Base64, carriage returns, trailing characters, missing headers, and malformed PIDs.
  - Honest claims: Attestations are parsed and stored as ATT-1 envelopes, but reported strictly as "attestation present, unverified" (V8 WARN). Never claims third-party timestamps or external assertions are verified.
  - Offline always: No network requests; all proof generation and locator checking operate completely locally.
  - Zero placeholders: Sweep over all new source files reveals zero `TODO`, `FIXME`, or mock implementations.
  - Error code registry: All exceptions use codes registered in `ERROR_CODE_REGISTRY` (e.g. `ENVELOPE_INVALID`, `CITE_RANGE`).
- **What-Not-To-Do Checks**:
  - Binary I/O: All proof and attestation writes/reads use `.read_bytes()` / `.write_bytes()` with strict UTF-8 decoding to avoid CRLF translation on Windows.
  - Strict Base64: Uses `strict_b64encode` and `strict_b64decode` to prevent non-canonical encoding padding bypass.
  - Schemas: Valid Draft 2020-12 schemas created for `cite`, `proof`, and `attest`. All CLI `--json` outputs pass schema validation.

- Tampered envelope lines or carriage returns in ATT-1 and TFP-1 trigger `ENVELOPE_INVALID` and fail closed.
- Vectors and fixtures remain pristine and read-only.
