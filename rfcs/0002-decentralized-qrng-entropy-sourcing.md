# RFC-0002: Decentralized, Publicly Verifiable QRNG Entropy Ingestion Without Centralized Oracles

- **Status:** Open Challenge (Strawman Review)
- **Author:** Aethel Protocol Working Group
- **Category:** Cryptography / Entropy Distribution
- **Affects:** Key Generation, Nonce Freshness, Timestamp Ordering / Yellow Paper §9, §11

---

## 1. Abstract

Post-quantum digital signatures (NIST FIPS 204 ML-DSA and FIPS 205 SLH-DSA) and distributed attestation networks require high-assurance, unpredictable entropy. While pure signing operations can be made pseudo-deterministic using synthetic nonces ($K = \text{HMAC}(sk, M)$), time-stamping, verifiable delay proofs, and decentralized key generation schemes require fresh physical entropy.

Quantum Random Number Generators (QRNG)—based on quantum optical phase fluctuations or photon beam-splitter measurements—provide true physical indeterminism. However, integrating QRNG into trust-minimized, decentralized networks presents a fundamental bottleneck:
- **Centralized Beacon Vulnerability**: Relying on public beacons (e.g. NIST Randomness Beacon, ANU Quantum Random Numbers, Cloudflare LavaRand) introduces a centralized oracle that can secretly pre-generate numbers, bias outputs, or suffer service denial.
- **On-Chain Blockhash Manipulation**: Using block hashes (e.g. Ethereum `prevrandao` or Bitcoin headers) exposes the protocol to miner/validator lookahead bias, where block producers selectively omit blocks to game the entropy.
- **Commit-Reveal Griefing**: Classic multi-party coin-tossing protocols suffer from the "last-revealer problem," where the final participant can withhold their secret after seeing everyone else's input.

How can a globally distributed peer-to-peer network source, verify, and combine quantum-grade entropy without trusted hardware and without single-point oracle choke-points?

## 2. The Provocative Baseline (Cunningham's Law Strawman)

To expose the engineering trade-offs, we present the following naive **Federated QRNG Threshold Beacon (FQTB-1)**:

```
[QRNG Node 1] ---> Hardware Stream s_1
[QRNG Node 2] ---> Hardware Stream s_2   ===>  Consensus Committee (k-of-n)  ===>  Output = H(s_1 ^ s_2 ^ ... ^ s_k)
[QRNG Node n] ---> Hardware Stream s_n
```

### Proposed Protocol
1. A consortium of $N = 7$ academic institutions each operate a commercial USB/PCIe QRNG hardware module (e.g. ID Quantique Quantis or Toshiba QKD-QRNG).
2. Every epoch $t$ (e.g., every 10 seconds), each node reads 256 bits of raw entropy $e_i^{(t)}$ from its local device.
3. Node $i$ signs $e_i^{(t)}$ using ML-DSA-87 and broadcasts `(epoch, i, e_i, signature)`.
4. Once any client collects $k = 4$ valid signatures from distinct nodes for epoch $t$, the final epoch entropy is defined as:
   $$E^{(t)} = \text{SHA3-256}\left(\bigoplus_{j=1}^{k} e_{i_j}^{(t)}\right)$$
5. The resulting $E^{(t)}$ is published as the global beacon value.

## 3. Why This Baseline Fails Under Cryptographic Attack

Engineers in distributed systems and cryptography will spot multiple vulnerabilities immediately:

### 3.1 The Adaptive Majority & Selective Disclosure Attack
Because the formula uses XOR before hashing, any single adversarial participant who observes the inputs of the other $k-1$ honest nodes can craft their own $e_{\text{adv}}$ to force specific bits or properties on $E^{(t)}$. In FQTB-1, if the network broadcasts raw values without a zero-knowledge commitment phase, the node with the lowest network latency controls the entropy.

### 3.2 The Quantum "Black Box" Problem (Device Spoofing)
How does a peer verify that a node's stream is actually generated by quantum mechanics rather than a pseudo-random seed like `ChaCha20(seed)` or a pre-computed playback dictionary?
- Standard statistical tests (NIST SP 800-22, Dieharder) cannot distinguish true quantum entropy from a high-quality PRNG or AES in counter mode.
- Unless the protocol utilizes Device-Independent Quantum Random Number Generation (DI-QRNG) based on Bell inequality violations (Clauser-Horne-Shimony-Holt tests), the "quantum" claim is pure marketing and easily forged.

### 3.3 Network Partitioning & Liveness Denial
If 4 out of the 7 nodes lose internet connectivity or face coordinated DDoS attacks, entropy generation halts completely. The protocol provides zero forward-progress fallback mechanisms.

## 4. The Open Architectural Inquiries

We invite rigorous proposals, formal protocols, and adversarial analysis addressing:

1. **Practical Device-Independent Entropy Proofs**: Can Bell-test violations or entanglement-certified witness proofs be verified efficiently on standard consumer CPU nodes without specialized quantum optical hardware at the verification layer?
2. **Asynchronous Verifiable Delay Function (VDF) Mixing**: Can we combine unverified local QRNG inputs with post-quantum VDFs (e.g. isogeny-based or hash-based Wesolowski/Pietrzak variants) such that no participant can evaluate the final output before the commitment window closes?
3. **Threshold BLS vs. Post-Quantum Drand**: While Drand (League of Entropy) achieves decentralized randomness via Boneh-Lynn-Shacham (BLS12-381) pairings, pairing-based cryptography is vulnerable to Shor's algorithm. What is the concrete protocol for a **post-quantum distributed randomness beacon** using lattice-based threshold signatures without prohibitive message expansion?
4. **Economic Slashing vs. Statistical Outlier Detection**: What incentive mechanism penalizes a node that feeds pseudo-random or static noise while preventing false positives caused by natural quantum thermal drift?
